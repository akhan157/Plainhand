# Reachability matrix (U12)

Generated by `node scripts/u12-reachability.mjs --write` from the running registry and the files that expose it. `tests/test-u12-reachability.mjs` fails when an action gains no surface, loses its screen without a documented reason, or when this file names an action the registry no longer defines.

Registry actions: **88** (read 21 · write 31 · task 12 · candidate 24). Screen reach: direct 34 · route 36 · aggregate 12 · none 0.

## Surfaces

| Surface | Where | What reaches it |
| --- | --- | --- |
| Screen | `plainhand/web/**` | The action is called by name, or the client calls an `/api` route whose handler runs it. Read-only actions the screens render from `/api/state` are listed as `aggregate`. |
| Conversation | `plainhand/agent.mjs` | Every action is in the model’s catalogue. Read and write run as tools; writes need the candidate’s confirmation; tasks need confirmation and run in Plainhand; candidate-tier actions return a panel link and change nothing. |
| MCP local | `plainhand-mcp.mjs` → `/api/mcp/actions` | Read, write and candidate actions. Task-tier actions are not tools: the agent is told to run them in Plainhand. Candidate actions return a link and steps. |
| MCP hosted | `plainhand/cloud/mcp.mjs` | Same set as the local bridge, over the hosted connector. |
| CLI | `bin/plainhand.mjs`, `package.json` | The launcher starts the app (screen and HTTP API); `plainhand-mcp.mjs` is the stdio MCP server. Scripted career-ops commands exist for some areas (`npm run doctor`, `verify`, `resume:*`, `scan`, `liveness`, `patterns`, `calibrate`, `update:check`, `demo:sample`). |

Tier rules are enforced once, in `registry.run`: candidate actions only from the screen; agent writes and tasks need explicit confirmation; MCP cannot run tasks. No surface can widen them.

## Documented unsupported interfaces

- Hosted: no application browser, no local files, and no CLI; task-tier actions run only in Plainhand.
- MCP: no task execution, no packet or understanding approval, no submission confirmation, no widening of shared context.
- CLI: no per-action command; the launcher serves the same API the screen uses.
