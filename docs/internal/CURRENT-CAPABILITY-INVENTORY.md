## Method and limits

- **Read, not executed.** No test, benchmark, browser, model or server was run. "Tests declared" means a `test(...)` exists at the cited line; it says nothing about whether it passes today. Counts are declarations found by `grep`, not results.
- **No live behavior is claimed** from source or tests. Anything a row says a mechanism "does" means the code is written to do it.
- **Mechanism located is not a pass.** "Carryable" means the code path exists on base and may be re-measured. It does not carry a historical PASS.
- **Scope split.** *Local*: source mechanisms and bounded fictional probes for all U rows are actionable here; these do not close every acceptance requirement. *External*: actual user-voice acceptance and human judge ratings require people. Commercial access and a permitted CAPTCHA environment limit only those access tiers; local realistic fixtures and safe handoffs proceed. Real employer submission is prohibited and is not a completion requirement. The result doc names each and what would unblock it.
- Line numbers are for `e4da45f` unless a SHA prefix says otherwise. Commits named as introducing a file are the last `git log` hit that implements it, not necessarily the first; several files first appear in the squashed 1.0 baseline `485668cbf3ce4181c3457ada8419a3d05493620d`.
- **Disposition rule used on every row.** `in_progress` when a mechanism for the requirement is located in source (or on an unmerged branch) and the row's evidence is missing. `not_run` when no mechanism is located, or the requirement is a measurement with nothing yet run. These are proposals; root decides and registers. No row is proposed PASS.
